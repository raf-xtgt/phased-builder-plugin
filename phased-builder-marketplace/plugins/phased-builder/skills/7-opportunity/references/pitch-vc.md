# Pitching Investors: Agent Reference

Read `research-rules.md` first. Not investment or legal advice; say so once.

## 1. Readiness check (honest)
Ask about stage, traction, team, and what they want (amount, use of funds). Say plainly if the project is
likely too early for VCs at this stage, and what usually comes first (users, revenue signals, a co-founder,
an accelerator). The user decides whether to pitch anyway.

## 2. Research the investors (if specific ones are named or wanted)
For each: stage and check size, sectors, regions they invest in, recent investments, portfolio conflicts,
how they want to be approached (warm intro, form, email). Search and cite. Flag region limits early.

## 3. The story
Interview the user for each part, in their words:
- **One-liner:** what it is, for whom, why it's different.
- **Problem:** who has it, how painful, evidence.
- **Solution:** what the product does today (from `PRODUCT.md`), the kernel.
- **Why now:** what changed that makes this possible or urgent.
- **Market:** size estimate built bottom-up (number of customers × price), with cited sources for any figures.
- **Traction:** real numbers only, from the user. None yet is a valid answer; say what will be measured.
- **Business model:** who pays, how much, why.
- **Competition:** real alternatives, including "doing nothing" and spreadsheets; why this wins.
- **Team:** why these people.
- **The ask:** amount, instrument if known, what it pays for, what milestone it reaches.

## 4. The deck outline
A common investor-deck order (10–12 slides): title/one-liner, problem, solution, demo/product, why now,
market, business model, traction, competition, team, the ask. Write it to
`opportunities/<name>/drafts/deck-outline.md`: one section per slide with the headline, 2–3 points, and
the visual to use. If the user wants actual slides, build them as a separate step.

## 5. Likely questions
Write `drafts/qa-prep.md`: the 10–15 questions investors are likely to ask this project (weakest points first),
with the user's answer notes. Include hard ones about competition, defensibility, and why this team.

## 6. Gaps
Product gaps that would strengthen the pitch (a demo-able feature, analytics to measure traction) become
roadmap phases via `2-scope`. Everything else is a task list for the user.
